# ClashLegends V1

网页大厅支持完整的经典模式 AI 对战和双人邀请房。玩家在晴昼峡谷出战，房间备战可以从 100 张卡和 106 个技能选项中配置八张出战卡。

## 独立 2D 内核

[内核结构与运行说明](docs/battle/README.md) · [交互矩阵](docs/battle/机制矩阵.md) · [旧版主动技能索引](docs/battle/旧版主动技能索引.md)。运行 `cargo run --locked --release -p clash-battle-core --example classic` 可让两个机器人使用手牌和主动技能打完一局。运行 `cargo run --locked -p clash-lobby --example battle_view` 后，多个浏览器可在[本地对局观察页](http://127.0.0.1:4318/)观看同一局。大厅中的真人对局由 Rust 宿主按每秒 20 个逻辑步推进。

## 本地运行

在这台 Mac 上，双击桌面的 **ClashLegends** 图标即可进入本地管理员大厅。应用复用开发数据库，按需构建项目，并从本机账号文件登录 `admin`。关闭游戏窗口后，大厅服务继续运行。同一 Wi-Fi 下的手机可在浏览器打开 `http://<Mac 的局域网 IP>:4317/play/`，首次访问以游客身份进入。

首次安装桌面图标或移动项目后，在项目根目录运行 `python3 tools/macos/install.py`。安装需要 Xcode 命令行工具。启动日志位于 `.local/desktop/`。

### 在自己的 iPhone 上用管理员图标

1. 在 Mac 游戏的 **ClashLegends → 配对我的 iPhone…** 菜单生成安装文件。Finder 会选中 `ClashLegends.mobileconfig`。通过隔空投送把它发给自己的 iPhone。也可以在项目根目录执行 `python3 tools/macos/phone.py` 生成同一文件。
2. 在 iPhone 的「设置 → 已下载描述文件」中安装。文件会添加游戏的主屏幕图标和这台 Mac 的开发证书。到「设置 → 通用 → 关于本机 → 证书信任设置」启用 **ClashLegends Local Game**。
3. 在同一 Wi-Fi 下，24 小时内首次点图标，游戏会自动配对并进入管理员大厅。之后从图标打开会沿用这部手机的会话。会话约 30 天后到期，或手动退出账号后，可以重新生成并安装文件。普通局域网链接继续作为游客入口。

手机图标通过 Mac 的 Bonjour 主机名访问 4319 端口，支持 HTTPS 和对局 WebSocket。桌面应用启动时会恢复已配置的手机入口。私有安装文件和服务日志在 `.local/phone/`。安装文件含有一次性管理员邀请，只发给自己的手机。

使用 Rust、Node.js（本项目验证环境为 Node 26）、npm 和 PostgreSQL 16。从本目录执行。首次可通过 Docker 建立专用开发数据库：

```sh
docker run -d --name clashlegends-v1-lobby-db \
  -p 127.0.0.1:55432:5432 \
  -e POSTGRES_USER=clash_lobby -e POSTGRES_PASSWORD=clash_local_dev \
  -e POSTGRES_DB=clash_lobby \
  -v clashlegends_v1_lobby_pgdata:/var/lib/postgresql/data postgres:16-alpine
```

这组凭据仅用于本机开发。如果已有上述容器，使用 `docker start clashlegends-v1-lobby-db`。已有独立数据库时直接指定自己的连接串。服务启动时创建大厅表。

```sh
npm --prefix web ci
npm --prefix web run build
export DATABASE_URL=postgresql://clash_lobby:clash_local_dev@127.0.0.1:55432/clash_lobby
cargo run --locked -p clash-lobby
```

打开 [本地大厅](http://127.0.0.1:4317/play/)。同一个浏览器的标签页共用游客身份。体验好友对战时，一方使用普通窗口，另一方使用无痕窗口或另一款浏览器，通过邀请码加入。测试手机局域网访问时，以 `LOBBY_ADDR=0.0.0.0:4317` 启动服务，在同一网络用电脑的局域网地址打开，数据库仍只绑定回环地址。

前端开发可额外运行 `npm --prefix web run dev`，Vite 将 API 和 WebSocket 代理至本机 Rust 服务。网站整合时，将同一域名的 `/play/`、`/api/` 指向大厅，并为 `/api/live`、`/api/matches/{id}/live` 和 `/api/recordings/{id}/play` 转发 WebSocket 升级请求。

## 游客与内测账号

默认直接进入游客大厅。点右上角头像可以选用卡牌头像或上传图片，填写最多 120 字的简介。游客的头像、简介、四套卡组、游戏设置和回放收藏保存在当前浏览器，清除站点数据会清除这些内容。在线对战使用服务端会话、房间席位、对局进度和指令日志。对局视频保存在录制设备上，按游客和账号分别显示。

账号登录由服务端的 `LOBBY_ACCOUNTS_FILE` 开启。未设置时大厅只显示游客资料。仓库提供本地凭据生成工具，在新环境运行一次：

```sh
python3 tools/provision_accounts.py
```

默认在 `.local/accounts/` 预留 `admin` 和三名内测玩家 `beta-01` 至 `beta-03`。可通过 `--beta` 指定内测人数，`--directory` 指定新目录。生成工具会保留已有目录中的密钥。登录名和独立随机密钥见 `login-keys.txt`，服务端只需要含角色和密钥摘要的 `registry.json`。`.local/` 已加入 Git 忽略规则。

准备开放内测时，用以下方式启动服务，通过「玩家资料 → 内测账号登录」登录。跨设备使用同一账号可恢复头像、简介、四套卡组和设置；退出账号会回到本机游客。对外访问账号使用 HTTPS。启用账号时，开发工作台需同时满足服务端已开放工作台且登录者为管理员。

```sh
LOBBY_ACCOUNTS_FILE=.local/accounts/registry.json cargo run --locked -p clash-lobby
```

## 从备战到结算

1. 在大厅选择「对战 AI」或创建好友房，即可进入备战。好友房的邀请码在开局按钮上方，也可以在「房间」中复制邀请链接。
2. 上方两行四列是出战卡组，下方四列卡池可按兵种筛选、按费用或名称排序。点卡牌可查看信息或移入移出卡组，也可先点空位，再从卡池选牌。随机图标生成八张不同的卡。点 1–4 切换卡组，点名称直接编辑（最多八个字）。切换时保留各套草稿，当前标签页进房会采用所选编号的已保存卡组。点「保存预设」才会更新该套内容，并将它设为新标签页的默认卡组。空卡组和缺牌卡组都能保存，凑齐八张才能准备。前两个符文卡位携带选定技能，单位部署后以 D、F 激活，法术在出牌时应用对应强化。
3. 玩家确认卡组后自动连接战场，同时准备本席位的模型和动作。好友房在双方资源就绪后开局。加载失败时可以重试或返回房间，已开局的比赛支持重连。Q/W/E/R 或点击手牌进行选择，再点击战场出牌；重复选择可取消。双方视角均为己方水晶在下。主动槽对应卡牌部署完成后，可以按键或点技能按钮释放。
   局内沿用旧项目 720×1280 的构图。晴昼峡谷底图由原版 54° 战斗相机导出，调试单位和点击落点使用同一地面投影。底部 160 设计像素放置下一张、四张手牌和十格金币条，左右圆形技能按钮随部署出现，显示金币消耗、剩余次数和冷却。可点击图标，也可使用设置中的快捷键。

4. 结算页显示胜负、原因和用时。「返回房间」以原席位和卡组继续下一轮。在对局中刷新或回到大厅，可以重新进入同一局。

## 大厅交互与游戏设置

顶部的“设置”可以调整总音量、音效音量和预留的背景音量，修改后立即生效，可用“试听音效”确认。大厅使用 Web Audio 播放短交互音，背景音轨后续接入。默认对局键位为四张手牌 Q/W/E/R、两个主动槽技能 D/F，支持重新绑定、冲突提示和恢复默认。游客偏好保存在本机，登录后的偏好保存到对应账号。战场读取同一份键位设置。

AI 对局、双人对局和工作台共用战斗音效播放器。近战兵和远程兵共用生成音，普攻使用各自兵种和阵营的音源，艾希有部署、普攻、万箭齐发和死亡音，防御塔有攻击、两段受损和摧毁音。首次点击或按键后启用声音。音量跟随“音效音量”，左右声像跟随本方视角。重连从新快照接续，在途弹体仍可按实际命中发声。卡牌和法术共用旧项目导出的音频配置。区域、弹体和单位的持续声按战场时钟恢复。摧毁水晶后，双方各自听到胜利或失败播报。[音频系统规划](docs/battle/音频系统规划.md)

大厅下拉选项与离房确认都由网页绘制。站内离开未保存的备战编辑器时可以取消或明确放弃；直接刷新或使用浏览器前进、后退，会在当前标签页保留草稿。

## 对局录制

在备战页的「录制设置」选择自动保存回放、录制视频或同时开启。局内「录制」也能手动保存本场回放或开始、停止录像。大厅的「我的录制」可打开已保存的内容。

- **对局回放**默认开启。服务端用冻结的卡组、随机种子、规则版本及双方的带时刻指令重演比赛，包含 AI 已经作出的决定和主动技能施放。时间轴支持跳转、暂停及 0.25、0.5、1、2、4 倍速。正在进行的比赛可以查看打开回放时已经保存的部分。回放需要连接匹配规则版本的大厅服务。
- **对局视频**默认使用 720 × 1280、30 FPS，可以调整画幅、清晰度、帧率、游戏音轨及手牌计时器。结算后视频存入录制设备的浏览器，支持预览与下载。在回放里开启「自由镜头」可以绕场旋转、平移、缩放，点击「录制视频」可拍下所选镜头。

## 代码入口

- [网页入口](web/src/main.tsx) 管理游客会话、页面与连接恢复。大厅、房间、编辑器和对局使用独立页面组件。
- [内容目录](content/catalog.json) 是这一版公开卡牌、技能和地图的共同输入。[导入工具](tools/import_catalog.py) 使用相邻的旧项目网站快照及既有美术资产生成卡池与缩略图，日常启动只依赖 V1 自身文件。
- [领域规则](server/src/model.rs) 校验卡组、模式与地图，生成 AI 卡组、私有视图和冻结配置。[房间服务](server/src/room.rs) 负责入席、准备、锁定与撤销。每次修改在事务中锁定房间；每轮有唯一比赛记录。
- [身份与预设](server/src/session.rs) 管理游客 cookie、旧版预设读取以及 WebSocket 心跳。[内测账号](server/src/accounts.rs) 管理登录、角色和账号数据。服务端推送更新通知后，浏览器读取按席位裁剪的最新快照。准备中的玩家失联约 20 秒后清除准备，席位默认保留 120 秒；可用 `LOBBY_GRACE_SECONDS` 设置总保留时长。
- [数据库与交接](server/schema.sql) 保存游客、卡组、房间和比赛。[对局宿主](server/src/battle.rs) 在双方就绪后原子认领比赛，按席位发送快照。每个开发库运行一个宿主。每次玩家命令及空闲时每秒记录进度；服务重启后按冻结配置、命令和机器人决策恢复。胜负与房间下一轮在同一事务中提交。

## 验证

```sh
cargo test --locked
npm --prefix web run build
npm --prefix web run test:lobby
npm --prefix web run test:settings
```

浏览器用例要求本地已安装 Chrome 且大厅正在运行，默认访问 4317 端口，可用 `LOBBY_URL` 覆盖。用例建立独立游客并写入开发库，覆盖移动视口 AI 备战、卡组及技能保存、好友邀请、满房、不同席位卡组、重复与同时准备、重连、QWER/DF、两种模式的实际终局和重新组局。整局浏览器用例按正常比赛时钟运行。

在启用了工作台的本机测试宿主上运行 `node web/tests/battle-audio.mjs`，可复验持续声、前摇取消、模型离手、实际命中、双席位声像和重连。设置 `AUDIO_SCENARIOS=layers` 可单跑持续声，`AUDIO_FINISH=1` 会继续到终局并核对水晶爆炸与播报间隔，`AUDIO_CAPTURE=/tmp/clash-audio` 会保存带声录像。在仓库根目录运行 `node web/tests/audio-roster.mjs` 可核对逐卡命名事件和普攻分段。整局用例支持用 `AUDIO_EVIDENCE` 输出浏览器播放记录；审计读取同一路径时也会检查播报及全部音源池。

工作台的“音效试听”可按对象、阵营、形态、事件与变体播放原片段。`node web/tests/audio-library.mjs` 用 Chrome 复验试听和全部打包片段的边界。

音效随仓库打包。要刷新素材，在旧项目可用且已安装 Godot、FFmpeg 和 ffprobe 的环境运行 `python3 tools/import_battle_audio.py`。导入器读取旧项目实际选用的 WAV 和 OGG，生成无损 FLAC、按采样点计数的片段索引，以及宿主使用的技能音效映射。附加 `--verify` 可逐段校验原素材与当前包里的 PCM。[素材导入工具](tools/import_battle_audio.py)

## 卡牌开发工作台

[小兵与建筑模型审查清单](docs/battle/小兵与建筑模型.md)列出了单兵、地图建筑及可部署建筑的模型、阵营差异和重建方式。

从本机大厅顶部进入「开发工作台」，也可以直接打开 `/play/workbench`。每个标签页有独立实验场，刷新会重建场地，浏览器保留最多八个快捷槽。监听回环地址时默认开放，局域网开发可设置 `LOBBY_WORKBENCH=1`，显式关闭使用 `LOBBY_WORKBENCH=0`。

- **实战观察**　默认选中艾希。部署后自动运行。在「场景与事件」点击「重建场景」摆好艾希和敌方木桩，战场上方可清场或暂停，暂停后可单步推进 50 毫秒。各页共用顶部的「选择对象」，支持按名称、ID 和分类查找卡牌、衍生物与系统对象。实战选择可部署对象会加入空余快捷槽，数字键 1–8 切换待放置卡。切换红蓝方后可在地图空地部署，法术可选择普通或携带技能的版本。选择模式可点选场上成员，施放主动或单独施加控制。战斗事件记录起手、出手、命中和死亡的 Tick，画面左下显示当前浏览器的渲染统计。
- **模型与动作**　选择对象、阵营与形态，可播放当前模型的原生动作和项目组合片段。已绑定的动作排在前面，其余标为「未接入」。拖动时间轴可查看完整片段，拖动模型旋转，滚轮缩放。预览包只在工作台打开模型时读取，正式对局按卡组、技能和场上出现的单位加载。
- **特效预览**　查看当前对象关联的 LoL 原生粒子，按发射器开关、缩放、暂停或单步。实战观察中的「判定范围」会在特效上画出法术和持续区域的边界及弹体位置，方便核对表现。[原生特效系统](docs/battle/特效系统.md) · [经典模式覆盖表](docs/battle/特效覆盖.md)
- **音效试听**　按阵营和形态平铺展示事件，点击任一变体立即试听，可以拖动进度条定位，暂停后从当前位置续播。
- **卡牌资料**　在同一页查看当前对象的属性、不同形态数据、被动和主动技能，也可打开大厅的卡牌信息面板。切离实战页及打开选牌框会暂停实验时钟，返回后恢复之前的运行状态。

工作台跳过手牌、金币、兵线和终局判定。主动技能可反复施放，无冷却和次数限制，部署、施法动作、控制和技能自身的触发条件仍按实战规则执行。费用、手牌资格与联网同步在正式对局验证。

工作台的「卡面摄影」支持编队布景、候选 GLB、动作定格、保存构图，以及导出 308×560 PNG。制卡时可对照卡池、详情与手牌裁切，再登记选中的原图或摄影成片。[新卡素材与卡面](docs/tools/新卡素材与卡面.md)
