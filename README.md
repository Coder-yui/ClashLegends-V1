# ClashLegends V1

网页大厅支持完整的经典模式 AI 对战和双人邀请房。玩家在晴昼峡谷出战，房间备战可以从 100 张卡和 106 个技能选项中配置八张出战卡。

## 独立 2D 内核

[内核结构与运行说明](docs/battle/README.md) · [交互矩阵](docs/battle/机制矩阵.md) · [旧版主动技能索引](docs/battle/旧版主动技能索引.md)。运行 `cargo run --locked --release -p clash-battle-core --example classic` 可让两个机器人使用手牌和主动技能打完一局。运行 `cargo run --locked -p clash-lobby --example battle_view` 后，多个浏览器可在[本地对局观察页](http://127.0.0.1:4318/)观看同一局。大厅中的真人对局由 Rust 宿主按每秒 20 个逻辑步推进。

## 本地运行

使用 Rust、Node.js（本项目验证环境为 Node 26）、npm 和 PostgreSQL 16。从本目录执行。首次可通过 Docker 建立专用开发数据库：

```sh
docker run -d --name clashlegends-v1-lobby-db \
  -p 127.0.0.1:55432:5432 \
  -e POSTGRES_USER=clash_lobby -e POSTGRES_PASSWORD=clash_local_dev \
  -e POSTGRES_DB=clash_lobby \
  -v clashlegends_v1_lobby_pgdata:/var/lib/postgresql/data postgres:16-alpine
```

这组凭据仅用于本机开发。如果已有上述容器，使用 `docker start clashlegends-v1-lobby-db`。已有独立数据库时直接指定自己的连接串。服务启动时创建大厅表。

```sh
npm --prefix web ci
npm --prefix web run build
export DATABASE_URL=postgresql://clash_lobby:clash_local_dev@127.0.0.1:55432/clash_lobby
cargo run --locked -p clash-lobby
```

打开 [本地大厅](http://127.0.0.1:4317/play/)。同一个浏览器的标签页共用游客身份。体验好友对战时，一方使用普通窗口，另一方使用无痕窗口或另一款浏览器，通过邀请码加入。测试手机局域网访问时，以 `LOBBY_ADDR=0.0.0.0:4317` 启动服务，在同一网络用电脑的局域网地址打开，数据库仍只绑定回环地址。

前端开发可额外运行 `npm --prefix web run dev`，Vite 将 API 和 WebSocket 代理至本机 Rust 服务。网站整合时，将同一域名的 `/play/`、`/api/` 指向大厅，并为 `/api/live` 和 `/api/matches/{id}/live` 转发 WebSocket 升级请求。

## 从备战到结算

1. 在大厅选择「对战 AI」或创建好友房，即可进入备战。好友房的邀请码在开局按钮上方，也可以在「房间」中复制邀请链接。
2. 上方两行四列是出战卡组，下方四列卡池可按兵种筛选、按费用或名称排序。点卡牌可查看信息或移入移出卡组，也可先点空位，再从卡池选牌。「随机」生成八张不同的卡，「预设」可保存或载入个人配置。前两个符文卡位携带选定技能，单位部署后以 D、F 激活，法术在出牌时应用对应强化。
3. 玩家准备后自动进入调试战场。好友房等两端连接后开局。Q/W/E/R 或点击手牌进行选择，再点击战场出牌；重复选择可取消。双方视角均为己方水晶在下。主动槽对应卡牌部署完成后，可以按键或点技能按钮释放。
   局内沿用旧项目 720×1280 的构图。晴昼峡谷底图由原版 54° 战斗相机导出，调试单位和点击落点使用同一地面投影。底部 160 设计像素放置下一张、四张手牌和十格金币条，左右圆形技能按钮随部署出现，显示金币消耗、剩余次数和冷却。可点击图标，也可使用设置中的快捷键。

4. 结算页显示胜负、原因和用时。「返回房间」以原席位和卡组继续下一轮。在对局中刷新或回到大厅，可以重新进入同一局。

## 大厅交互与游戏设置

顶部的“设置”可以调整总音量、音效音量和预留的背景音量，修改后立即生效，可用“试听音效”确认。大厅使用 Web Audio 播放短交互音，背景音轨后续接入。默认对局键位为四张手牌 Q/W/E/R、两个主动槽技能 D/F，支持重新绑定、冲突提示和恢复默认。偏好保存在当前设备的浏览器中，同源标签页共享。战场读取同一份键位设置。

大厅下拉选项、离房和删除确认都由网页绘制。站内离开未保存的备战编辑器时可以取消或明确放弃；直接刷新或使用浏览器前进、后退，会在当前标签页保留草稿。

## 代码入口

- [网页入口](web/src/main.tsx) 管理游客会话、页面与连接恢复。大厅、房间、编辑器和对局使用独立页面组件。
- [内容目录](content/catalog.json) 是这一版公开卡牌、技能和地图的共同输入。[导入工具](tools/import_catalog.py) 使用相邻的旧项目网站快照及既有美术资产生成卡池与缩略图，日常启动只依赖 V1 自身文件。
- [领域规则](server/src/model.rs) 校验卡组、模式与地图，生成 AI 卡组、私有视图和冻结配置。[房间服务](server/src/room.rs) 负责入席、准备、锁定与撤销。每次修改在事务中锁定房间；每轮有唯一比赛记录。
- [身份与预设](server/src/session.rs) 管理游客 cookie、私人预设以及 WebSocket 心跳。服务端推送更新通知后，浏览器读取按席位裁剪的最新快照。准备中的玩家失联约 20 秒后清除准备，席位默认保留 120 秒；可用 `LOBBY_GRACE_SECONDS` 设置总保留时长。
- [数据库与交接](server/schema.sql) 保存游客、卡组、房间和比赛。[对局宿主](server/src/battle.rs) 在双方就绪后原子认领比赛，按席位发送快照。每个开发库运行一个宿主。每次玩家命令及空闲时每秒记录进度；服务重启后按冻结配置、命令和机器人决策恢复。胜负与房间下一轮在同一事务中提交。

## 验证

```sh
cargo test --locked
npm --prefix web run build
npm --prefix web run test:lobby
npm --prefix web run test:settings
```

浏览器用例要求本地已安装 Chrome 且大厅正在运行，默认访问 4317 端口，可用 `LOBBY_URL` 覆盖。用例建立独立游客并写入开发库，覆盖移动视口 AI 备战、卡组及技能保存、好友邀请、满房、不同席位卡组、重复与同时准备、重连、QWER/DF、两种模式的实际终局和重新组局。整局浏览器用例按正常比赛时钟运行。

## 卡牌开发工作台

[小兵与建筑模型审查清单](docs/battle/小兵与建筑模型.md)列出了单兵、地图建筑及可部署建筑的模型、阵营差异和重建方式。

从本机大厅顶部进入「开发工作台」，也可以直接打开 `/play/workbench`。每个标签页有独立实验场，刷新会重建场地，浏览器保留最多八个快捷槽。监听回环地址时默认开放，局域网开发可设置 `LOBBY_WORKBENCH=1`，显式关闭使用 `LOBBY_WORKBENCH=0`。

- **实战观察**　默认选中艾希。点击「重建场景」摆好艾希和敌方木桩，点「继续战斗」观察连续出手，或在暂停时单步推进 50 毫秒。点击「选择实验卡」可搜索正式卡牌和系统对象，数字键 1–8 切换待放置卡。切换红蓝方后可在地图空地部署，法术可选择普通或携带技能的版本。选择模式可点选场上成员，施放主动或单独施加控制。战斗事件记录起手、出手、命中和死亡的 Tick，画面左上显示当前浏览器的渲染统计。
- **模型与动作**　选择对象与阵营，查看已打包的所有片段、实战用途和时长。拖动时间轴暂停定位，拖动模型旋转，滚轮缩放。模型来源和动作绑定与正式对局共用。
- **卡牌资料**　可独立搜索卡牌或系统对象，查看正式配置、属性和技能。切离实战页及打开选牌框会暂停实验时钟，返回后恢复之前的运行状态。

工作台跳过手牌、金币、兵线和终局判定，使用正式的部署、攻击、技能与表现事件。费用、手牌资格与联网同步在正式对局验证。
