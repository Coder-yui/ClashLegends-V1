# 浏览器战场表现层接入规划

2026-11-19 · 设计稿。实施分为模型与动画、音效、特效三个阶段。每阶段先跑同一小组代表单位，再按机制族覆盖经典模式。阶段一就进入真实 AI 和双人战场，保留 Canvas 调试视图作为几何与时序对照。

**三条基准各有用途。** V1 的 Rust 对局决定谁在什么位置、何时出手、命中、取消和死亡。LoL 原生素材决定此时角色怎么摆姿势、声音由哪些层组成、粒子怎样运动。ClashLegends 自己的设计决定选用哪个英雄或皮肤、怎样适配卡牌机制、尺寸、阵营和俯视视角。旧版的来源记录、已选造型和玩家确认过的细节可帮助找到原件，旧场景树与播放器的组织方式留给旧版。

## 从现有战场接到同一条时间线

| 已核对的现状 | 第一阶段要交付的接口 |
| --- | --- |
| 内核的单位视图已有位置、朝向、目标、活动、动作代次、起始 Tick、控制和攻移速。代次随活动切换或新一轮攻击增加，一次普攻可跨越多个代次。 | 给每个可见单位提供可恢复的动作描述，区分“当前活动”与“这一次攻击或施法”。跨前摇、释放、后摇使用同一行动标识，带技能或普攻变体、阶段起点和已知的释放时刻。形态、换弹、持续施法等按实际需要补公开状态。 |
| 正式宿主每 50 ms 推进一步，随后丢弃内核事件。玩家帧只传少量单位字段，普通弹体被压成阵营与坐标。内核已有带 Tick 和序号的攻击、发射、命中、死亡、变形等事件。 | 在宿主按席位生成表现快照与有序事件。弹体、扫掠和区域需要稳定标识、可见来源、位置或路径、方向、起始时刻、持续范围。逐一核对经典技能自己的波、区域与延迟结算，补它们实际发生的释放、取消和结束事实。 |
| 正式连接以最新快照覆盖旧快照。浏览器收到帧后重画 Canvas。 | 快照可以合并。瞬时事件进入每席位有界序列，按游标补送、去重；超过保留窗口就下发新基线与水位。刷新、重连或标签页回到前台时恢复当前姿势、在途弹体和有效循环，跳过基线之前的一次性释放音、闪光和死亡。 |
| 战场底图已按 54° 相机导出，CSS 已对地面纵向缩放。两个席位都把自己的水晶放在下方。 | 固定同一套逻辑地面、3D 地面、屏幕坐标的双向换算。模型脚底、武器挂点、空中高度、目标圈、血条和点地使用同一相机。第一批沿用现有底图，透明 3D 画布叠在上方，地面纵向投影只应用一次。桥头、塔基、场边在双方视角及不同手机比例下逐点校准。 |

浏览器按服务器 Tick 建一条稍滞后的播放时间线，先以两步缓冲（100 ms）试测，再按抖动和操作反馈调整。每个显示帧插值位置和朝向，按动作年龄求骨骼姿态，再采样挂点，最后派发这个时刻的表现事件。瞬移、显隐、形态替换有明确切点。事件晚到时，当前动作跳到相应年龄，过期的一次性提示按类型跳过。输入与选牌即时响应。UI 用 React，场内骨骼和弹体用独立渲染循环。

事件在**发生时**按双方可见性裁剪。死亡后仍可凭事件给出的末姿态或公开位置收尾；实体仅因失去可见性离开快照时只隐藏。不可见的来源、目标和对手未公开的牌组也从事件及预加载请求中裁掉。版本随回放记录固定，重复播放相同记录时从行动标识稳定选择同一动画和音效变体。调试回放使用已裁剪的表现记录，双方私有输入日志留在宿主。

依据见 [内核视图与事件](../../battle-core/src/model.rs)、[活动代次与席位视图](../../battle-core/src/lib.rs)、[经典区域与扫掠](../../battle-core/src/classic/zones.rs)、[正式宿主](../../server/src/battle.rs)、[网页战场](../../web/src/battle-field.tsx) 和 [地面布局](../../web/src/battle.css)。

### 通用动作系统怎样切换

每个角色同时记录三件事：**基础姿态**（待机、行走、追击或建筑静止），**当前行动**（攻击、引导、换弹、施法等及其阶段），**形态与控制**（使用哪套模型和动作、能否移动或继续行动）。表现端根据这三项和动作表选片。卡牌配置声明有差异的剪辑、过渡与标记，共用一套播放和清理逻辑。

| 权威状态或事件 | 选片与进入 | 退出或打断 |
| --- | --- | --- |
| 生成、部署、就绪 | 实体先落在权威位置，有部署片则播放，没有则用该造型的待机姿势。 | 部署期间重连，从已过时长开始；就绪时按当时活动转入待机、跑步或攻击。 |
| 待机、行军、追击 | 行军和追击可共用跑步循环。保留步态相位，按自主移动速度在角色允许区间内调速。推挤、击退独立处理。 | 起停优先选择源动画图中对应的转场片。短促转向只改变朝向；进攻立即从当时混合姿态接起手。 |
| 普攻前摇、释放、恢复 | 同一次普攻固定变体。将素材的松弦、枪口或刀锋接触帧对齐权威离手或打击 Tick。分别适配标记前后两段；合理区间外优先裁收势或选短片。 | 前摇取消立即放弃尚未释放的标记；释放后角色可以死亡或移动，箭按自己的 ID 继续。下一击到来可从当前后摇切入。 |
| 施法、持续引导、换弹 | 按技能和阶段选择起手、维持循环、退出片。可边走边施法的动作，源资源支持时用骨骼遮罩叠加上半身；全身片跟随权威位置移动。独立的弹匣状态驱动换弹。 | 自然结束按下一活动选回待机或跑步；被打断按该技能的中断边退出。对重施、连段给新的行动标识。 |
| 受控、位移、死亡、变形 | 死亡进入终止姿势并释放原行动。形态变化按事件切换造型或部件。冻结、凝滞、眩晕分别声明定格、隐藏或受控姿势；定身只约束移动，沉默按实际施法结果表现。 | 解除时从权威当前行动恢复。冲刺以权威路径移动，闪现直接换位；死亡画面由临时表现对象收尾，复生按新生命阶段进入。 |

每条过渡声明来源状态、目标状态、可中断时机、专用剪辑或混合时长，以及被打断时要撤销的局部标记。有原生过渡片时核对其首尾姿势和源图混合参数；无专片时以当前混合姿态短过渡。离散事件如箭离手、部件切换在指定时刻只执行一次。相同动作的连续快照只校准年龄。素材根位移仅用于局部视觉偏移，世界位置由权威轨迹提供。

**两个首批验收镜头**

- **艾希连续射击。** 从跑步接 Attack1，箭在松弦帧从已核实的手部挂点离开，再从收弓接 Attack2。分别录下松弦前受控、松弦后死亡、攻速变化、红方视角。用慢放检查箭与手分开的第一帧，用事件记录检查同一支箭的命中。阶段一用调试箭显示轨迹。
- **费德提克引导。** 源包内有 `fiddlesticks_spell2`、`spell2_channel`、`spell2_channel_toidle` 和 `spell2_to_run` 对应片段。目标消失后站定时接转待机；需要追击时接转跑；收势中重新起攻时从当时姿势切入。只有玩法产生对应末段时才选用末段动作。核对灯笼、舌头等由动画控制的部件显隐。

**阶段出口。** 先用近战兵、艾希、费德提克、一个双形态单位和一座塔，走通真实战场、双席位、重连与同记录慢放。再按骨骼兵种、英雄、建筑、形态、衍生物扩面。逐卡登记模型、动作、挂点与验收片段，法术卡登记其召唤物或标明无模型。关键释放点与权威时刻的差异初定 ≤1 个逻辑步；还要在原速和慢放中检查脚滑、跳姿、错手、穿地和取消后的残留。最后核对全卡组可达内容的覆盖表及性能基线。

## 阶段二 · 音效

当前协议、浏览器播放、素材制作及分批验收见[音频系统规划](音频系统规划.md)。

沿原皮资源表找到 Wwise 事件，追到事件库、媒体库或语言包。为每个用到的声音记录触发语义、变体选择、分层、延迟、增益、循环点和停止方式。能离线混合的固定层可烘为一个短音，需独立停止、随机或随状态变化的层保持独立。保留原事件相对响度，另记项目混音补偿。缺少对应原声的项目记录为静音或已有设计指定的替代。

| 声音归属 | 例子 | 生命周期 |
| --- | --- | --- |
| 本次行动 | 艾希拉弓、施法起手 | 跟行动标识调度。前摇取消时撤销尚未开始的声音；已发声部分按源事件停止或淡出。 |
| 已释放弹体或一次命中 | 松弦、飞行、箭命中 | 发射音只响一次。飞行循环跟弹体，命中音跟实际命中事件。射手离场后，已释放弹体继续拥有自己的声音。 |
| 持续状态或区域 | 琴女治疗光环、持续引导 | 生效时开一条循环，按归属在结束、打断或离开可见范围时停止。重连可从有效循环相位接回，结算和退场统一释放。 |

复用现有 Web Audio 的总音量、音效、背景总线与浏览器解锁流程，战斗 SFX/语音接音效总线。用播放时间线调度音频时钟。重复事件去重，同刻大量小兵普攻按同类并发上限与优先级分配声部，为关键施法和命中保留位置。按实际使用解码和复用音频缓冲；切后台再回来时恢复有效循环。首批以艾希三段普攻声、琴女持续声、密集兵线和连续退场验收。[现有混音入口](../../web/src/audio.ts)

**阶段出口。** 按源事件分轨试听，再把声音放回阶段一的录像核对。空放、取消、格挡、命中、死亡和断线分别听一次。检查高并发时关键音仍清楚，同一事件没有重响，三局后循环声部都已释放。按卡和技能记录音频覆盖、缺源与混音选择。

## 阶段三 · 特效

离线从皮肤资源映射追到粒子系统 BIN、发射器、纹理、网格与材质。逐层保留出生时刻、寿命、曲线、局部轴、朝向、跟随权重、深度测试和混合方式。按原语选择浏览器表示：简单粒子用批量精灵，能重复播放的复杂局部动画可离线采样，依赖目标距离、飞行速度或转弯历史的光束和拖尾运行时生成。不能复现的材质或发射器单列，与原件并排验收后决定替代方式。

| 归属与空间 | 样例 | 必须重现的行为 |
| --- | --- | --- |
| 角色骨骼或模型根 | 武器蓄力、琴女自身光环 | 按动作采样挂点；明确是否继承旋转、高度和缩放。粒子出生后按源层决定继续跟随还是留在世界位置。 |
| 弹体、双端连线 | 琴女 R、费德提克汲取 | 发射层、飞行层、命中层分别计时。发射取该帧挂点，飞行读取权威路径；光束两端分别解析。弹体结束后停止新增粒子，已生成尾迹按剩余寿命消散。 |
| 世界点、地面区域 | 落地冲击、冰柱、持续法阵 | 按公开的中心、朝向、边界和持续时间呈现。危险边界用玩法几何校准，装饰光晕可在边界外消散。独立落地效果可跨越施法者死亡。 |

**阶段出口。** 同看素材预览、V1 实战与权威范围叠图，逐项核对起手、释放、路径、命中、消散和取消。琴女 R 检查音符朝向、挂点、红方视角和运动拖尾；冰柱检查地面接触点、边界和退场；群体技能检查同帧透明叠加。低画质保留弹体、受控状态和危险范围辨识，优先减少装饰发射率、尾迹分段和透明层。最终按 100 张牌、106 个技能选项及它们可达的形态与衍生物核对三阶段表，区分已验收、设计上无此项、缺源、待修。

## 怎样确定浏览器承受得住

已有 32/64/128 单位压测计时区间只覆盖 Rust 逻辑。浏览器沿用这些密度，另加一场固定对局、同帧召唤与变形、首次遇到对方新单位、群体技能、标签页恢复和连续三局。固定设备与浏览器版本、分辨率/DPR、画质、网络和种子。桌面与实际手机分别测冷、热缓存，保留原速录像与逐帧曲线。

| 比较方式 | 每阶段记录 | 超出目标后先查什么 |
| --- | --- | --- |
| 同记录依次打开调试视图、静态模型、骨骼动画 | 客户端帧耗时 p50/p95/p99、长帧、动画求值用时、绘制调用、三角面、可见骨骼实例、可取得的 GPU 时间 | 分清 CPU 动画求值、GPU 绘制和首次上传。优先共享资源、控制材质数，对远小单位降低姿态采样频率；释放帧的武器挂点仍按目标时刻求值。 |
| 在动画基线上叠加音效，再叠加特效 | 解码峰值、活动声部、活跃发射器和粒子、透明覆盖、GPU 帧时、首次施法最慢帧 | 声部按重要性限流；特效按屏幕覆盖与生命周期分级。单独关停某一类后复测，记录节约了多少毫秒及牺牲的画面。 |
| 冷启动、首次出牌、反复进退对局 | 压缩传输字节、首个可操作画面和首个完整模型用时、纹理解码/上传峰值、JS 堆、纹理及音频估算驻留、第三局退出后的存活对象 | 分辨下载、解码和上传造成的停顿；检查重复引用、未回收的纹理、播放器、声部和场景对象。记录可测值和估算值各自的来源。 |

建议先以 60 Hz 桌面稳态帧间隔 p95 约 16.7 ms、手机低档 30 FPS 的 p95 约 33.3 ms 为试测目标，同时报告 p99、超预算比例和最长停顿。首轮在明确的目标机上实测后再定下载量、内存、声部和透明粒子的上限。每阶段保存相同视角的对比录像、时间点与增量成本；进入批量制作前审看原速手感和关键帧，遇到问题可定位到源资产、协议、转换或播放器。

**首个实施里程碑**定为一场可重放的“近战兵交战、艾希连续射两箭”小样：双方看见正确朝向，箭从手上离开，插入一次前摇取消、一次发射后死亡和一次在途重连，调试几何和正式模型能切换对照。它通过后，再用费德提克验证专用过渡与引导，用群兵验证骨骼成本，然后展开阶段一的其余内容。
