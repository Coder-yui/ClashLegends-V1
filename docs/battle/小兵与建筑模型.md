# 小兵与建筑模型审查

在本机大厅点「开发工作台」→「模型与动作」。直接打开 `/play/workbench?view=models&model=princess_tower` 可以从防御塔开始。用「上一个」「下一个」逐项检查，红蓝按钮切换阵营。在「实战观察」可检查地图尺度、落点、编队、遮挡和出手。

| 审查对象 | 内容 |
| --- | --- |
| 兵线与编队 | 近战兵、远程兵、炮车兵、超级兵，每种均有红蓝两套。小队按实际生成的成员显示。 |
| 地图建筑 | 双方防御塔、基地水晶。塔体有完整、两档受损和废墟模型。 |
| 可部署建筑 | H-28G 进化炮台、H-28Q 尖端炮台、德邦军旗、金币守卫、高地水晶、惊吓魔盒、凛冬之柱、火药桶、女王巢穴、草间人、灵魂触手、太阳圆盘、训练木桩、荆棘喷射者、墓碑、藤蔓鞭击者、兹若特传送门。高地水晶、太阳圆盘基座和训练木桩区分双方。 |

## 素材与动作

四种兵各自读取 Map11 中 Order / Chaos 的 SKN、SKL、原皮贴图和 Skin0 动画图。普通远程兵取法杖骨骼，原包蓝红离手标记分别在第 14.1 帧和第 14 帧，项目统一在第 14 帧创建弹体。炮车取 Cannon 骨骼和第 9 帧，超级兵两段普攻均取第 15 帧。帧号按源动画每秒 30 帧换算。出手与伤害仍由对局 Tick 决定。

建筑采用素材库已转换的模型与纹理，包括旧工作台使用的指定 GLB。离线工具提取所需模型部件，打成 V1 自包含 GLB。德邦军旗包含原旗面纹理和 E CameraTrail 一个稳定时刻的布面，凛冬之柱取原冰柱网格和升起、下沉轨道。防御塔废墟随当前快照恢复，太阳圆盘立在原塔位时共用已有地基。

动作选择来自旧项目的卡牌 `visual_animations`、地图建筑配置和模型包装脚本。V1 按权威部署窗口、攻击序号、施法时间、实际受伤及召唤事件驱动播放。工作台「模型与动作」列出已绑定片段及用途，可以暂停、拖动时间轴。「实战观察」选中单位后，战场下方显示播放器当前片段；防御塔另列仍在下落的碎块层。

| 对象 | 审查时可观察到的动作 |
| --- | --- |
| 近战、远程、炮车、超级兵 | 部署使用各自的 `Idle1`，行军使用 `Run`，连续攻击交替使用两段普攻。死亡窗口 0.5 秒。炮车使用两段 `_BASE` 普攻，超级兵使用 `Death_Base`。 |
| 防御塔 | 生命降至 2/3、1/3 和摧毁时，分别切换塔体并触发 `NativeBreak1/2/3`。各组只驱动自己的骨骼，可以同时下落。一次伤害跨档只触发到达的那档，重连直接显示当前塔体。 |
| 基地水晶 | 出生保持姿态 → 升起约 5.17 秒 → 待机。摧毁时切到破碎表面，按原片播放 8 秒并保留末姿态。 |
| H-28G 进化炮台 | 部署和双普攻；失去目标后收起，进入 `Deactivate_Idle`；目标进入时以 0.2 秒 `Activate` 唤醒。 |
| H-28Q 尖端炮台 | 部署、待机、普攻和死亡。施放「海克斯穿透激光」时播放独立的 `Attack_Beam`，以施法时间对齐出手。 |
| 草间人 / 远古恐惧 | 草间人部署使用 `respawn`；汲取从起手转为循环，停止后按移动或待机接不同收势；保留灯笼、舌头与手臂的原片显隐帧。 |
| 训练木桩、火药桶 | 受到实际伤害分别播放 `Hit`、`Timer`。持续自然掉血保持待机，致死打击进入死亡。 |
| 兹若特传送门 | 部署、待机、吐怪、死亡。实际召唤时将 `Spit` 叠加在持续待机上；死亡以原速播放 1 秒，末姿态保留至 2.2 秒。 |
| 太阳圆盘 | 部署升起，依旧版九段顺序轮换两段待机；双普攻只驱动圆盘上部，废墟底座保持朝向。死亡使用原片前 2 秒，压缩为 0.8 秒。 |
| 高地水晶 | 原升起片段 → `Idle_Normal1` → `Death_Base`；死亡取原片前 5 秒，压缩为 1 秒。 |
| 荆棘喷射者、藤蔓鞭击者 | 两种植物都从 `Up` 展开，前者单普攻，后者双普攻；荆棘喷射者还使用 `Buffbones` 的挂点初始姿态。 |
| 灵魂触手、惊吓魔盒 | 触手从部署进入愤怒待机，可以从任意待机相位衔接拍击。魔盒使用待机、单普攻和死亡。 |
| 金币守卫、德邦军旗 | 金币守卫使用原插眼、静态待机和死亡；军旗使用旗杆待机和死亡，布面保持固定轮廓。 |
| 凛冬之柱、墓碑、女王巢穴 | 冰柱升起、停驻、下沉。墓碑和女王巢穴各自使用部署、待机、死亡；空巢沿用原卡选定的洞穴待机和死亡。 |

男爵强化覆层、战斗粒子和声音留在后续表现阶段。

## 血条和水晶井口

地图塔和基地水晶始终显示当前生命。以当前玩家视角为准，己方塔的绿条在塔身，己方水晶的绿条在底座下方，敌方红条在建筑上方。塔宽 120，水晶宽 160，高度均为 18。有盾时，建筑在固定条宽内按生命上限和有效盾层容量分配空间。

一般单位按当前原生形态的视觉直径确定条宽。受伤、带盾或有技能资源等状态时显示，普通满血时隐藏。白盾紧接当前生命，真实超额生命用紫色，刻线标出正常满血位置。总量超过基础宽度的 1.5 倍后，生命和盾一起等比压缩。资源条维持基础宽度，左缘与血条对齐。

防御塔沿用水晶的视线裁切，井口半径取自原塔基内圈（1.04）。塔身与废墟开口内可见原生地下网格，太阳圆盘复用废墟时共用同一塔基。基地水晶和高地水晶的地下部分也按相机视线与地面的交点裁切。原版井口半径分别为 1.35 和 0.82 个模型世界单位；开场升起时，可以直接看到井内的地下模型。

## 单位标识与对局资源

部署白弧从十二点顺时针填充，半径为视觉半径加 6，宽 3。脚下阵营盘按观察席位显示蓝或红，透明度 0.72，在地面接受模型深度遮挡。保留原卡关闭阵营盘的配置。存活目标受击闪白 0.05 秒，同目标最多每 0.18 秒触发一次，塔和基地水晶的白色强度从 0.22 衰减。正式模型在加载期间也使用自身资源。

进入正式对局前，两端从冻结的卡组、前两个技能席、主动镜像、衍生单位与系统兵线计算出的同一份资源清单加载模型和动作。清单只传去重后的资源名。模型和基础动作共用一份，独立的施法包只在本局可用时准备。工作台准备当前实验对象的动作，模型审查页面另外提供艾希 Skin0 的 25 个动作入口（22 个不同的 ANM）。绿色条目已绑定新版动作系统，其他条目可以播放、暂停和拖动时间轴。

## 重建与验证

从仓库根目录运行以下命令。本机需安装项目 web 依赖和 lol-asset-tools。

```sh
node tools/model-resources.mjs
python3 tools/import_battle_models.py /Users/czh/Downloads/LOL_Asset_Source
python3 tools/import_building_models.py ../ClashLegends/assets
npm --prefix web run build
cargo test --workspace --locked
LOBBY_URL=http://127.0.0.1:4432 node web/tests/structure-models.mjs
LOBBY_URL=http://127.0.0.1:4432 node web/tests/structure-actions.mjs
LOBBY_URL=http://127.0.0.1:4432 node web/tests/health-bars.mjs
```

浏览器用例逐项加载 23 类对象的 32 个造型，检查实际渲染像素，并在同一实战渲染器里按正式定义部署。用例会打印截图目录。所有模型按需加载，同场同造型复用几何和纹理。
