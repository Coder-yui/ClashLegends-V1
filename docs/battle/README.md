# 2D 战斗内核

浏览器提交玩家意图，单局宿主持有一个 `ClassicMatch`，每秒推进 20 次。世界使用未投影的二维坐标。移动距离、碰撞半径、技能范围与弹速都在这个坐标系里计算。调试器可以画圆，正式客户端可以做镜头投影、模型插值和音画同步，两者读取同一份结果。

```text
大厅冻结的模式、地图、版本、种子、双方卡位与技能选择
  └─ 宿主按席位提交有序输入
      └─ ClassicMatch · 经典规则
          ├─ 玩家座位 ─ 手牌与队列、金币、部署区域、主动槽、命令回执
          ├─ 地图与阶段 ─ 双方塔位、兵线出生点、倒塔区域、加时与胜负
          └─ Battle · 固定步二维世界
              ├─ 实体定义 ─ 身体与层、视野、射程、行动、武器、技能、生命周期
              ├─ 感知 ─ 资格与来源 → 身体表面距离 → 锁定、追击或同路推进
              ├─ 行动 ─ 起手与出手、持续攻击、维持自疗、弹匣与换弹
              ├─ 空间 ─ 导航路线 → 局部转向 → 地形与同层接触 → 权威位置
              │        技能位移 → 途中约束 → 合法落点查询 → 到达或中断
              ├─ 技能 ─ 瞄准参数 → 资格 → 形状与过滤 → 一次或分阶段交付
              ├─ 结算 ─ 控制、护盾、生命、死亡、生产、形态与复生
              └─ 输出 ─ 按席位的快照、带 Tick 和序号的语义事件、输入回放
```

旧版基线为 `61bc6190`。[机制矩阵](机制矩阵.md)列出各系统的决定和验收边界。[旧版技能索引](旧版主动技能索引.md)覆盖大厅的 106 个主动选项、52 个旧实现族，用于逐卡迁移跟踪。

## 一步内发生什么

1. 推进逻辑时钟，到期的状态失效，检查形态恢复和已经排定的区域脉冲。
2. 经典规则推进经济，按宿主给定的顺序校验两个席位的命令。成功出牌才轮转手牌，成功施法才消耗费用和次数。此批生命变化一起提交，再按时刻派出兵线。
3. 推进部署、建筑衰减与周期生产。用共同的感知快照做单位决策，生成普攻、持续行动、弹体与语义事件。提交本批生命变化，处理死亡、衍生和复生。
4. 提交自主移动、外力与接触修正，按移动后位置裁定弹体命中。经典模式在步末判断水晶、塔数、加时或平局，再对外发布状态。每个批次的顺序都是规则的一部分。

## 接入与内容范围

`resolve_deck` 把已校验的八个有序卡位解析成可执行定义，前两个槽按选中的技能 ID 绑定。宿主负责把玩家身份映射到席位。两名机器人走同一条出牌、施法和扣费入口。每个席位只能读取自己的手牌与下张牌。世界原始事件供可信宿主消费，对外广播前需按观看者裁剪。

本地观察页共用一局、支持刷新，只展示公开几何与结局。[大厅对局宿主](../../server/src/battle.rs) 使用游客会话验证冻结席位，并从 100 张实战卡中解析双方各八张出战卡。卡牌数值由旧项目的 gameplay 定义导出至 [battle_rules.json](../../content/battle_rules.json)，部署、攻击、技能和结算在 Rust 内核执行。正式入口支持玩家对 AI 或双人对局，按席位推送战场与私有手牌，接受带顺序号的指令，并把结算结果写入 PostgreSQL。完整操作见[大厅运行说明](../../README.md)。回放绑定规则、内容版本、地图 ID、种子、双方卡序和主动选择。固定构建内已验证，跨平台逐位重放兼容性尚未验证。

## 运行与复验

从项目根目录运行。内核和本地观战示例均可脱离 PostgreSQL。

```sh
cargo test --locked -p clash-battle-core
cargo run --locked --release -p clash-battle-core --example classic
cargo run --locked -p clash-lobby --example battle_view
```

第三条命令启动后，用两个浏览器打开 [本地对局观察页](http://127.0.0.1:4318/)。点选单位可检查它当前处于推进、追击或攻击的哪一阶段。蓝圈与金圈分别画出从身体边缘向外计算的视野和射程，虚线连接当前目标。端到端用例自行启动独立宿主，比较 Chrome 和 Edge 收到的相同 Tick、终局 Canvas 像素及重连结果。路径测试将 Rust 搜索结果与旧版 44 组原生夹具逐节点比较。

```sh
node web/tests/battle-view.mjs
cargo run --locked --release -p clash-battle-core --example bridge_load
```

压测记录单局逻辑步 p50、p95、p99、最大耗时及超过 50 ms 的步数。覆盖 32/64/128 个桥头单位、完整经典对局、同一步 12 次变形和 72 次召唤。机器人决策、网络传输和浏览器渲染在计时区间外。

### 本机单局基线

2026-11-18 在 Apple Silicon 上以 release 构建测得，单位为毫秒。固定种子 `20261118` 的代表对局持续 3548 步，成功出牌 70 次，生成 62 个衍生单位，红方摧毁蓝方水晶。整组压测进程的峰值常驻内存约 3.7 MiB。

| 场景 | 采样步数 | p50 | p95 | p99 | 最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 32 单位桥头 | 1200 | 0.029 | 0.064 | 0.129 | 0.465 |
| 64 单位桥头 | 1200 | 0.047 | 0.088 | 0.179 | 0.349 |
| 128 单位桥头 | 1200 | 0.131 | 0.180 | 0.375 | 0.619 |
| 完整经典对局 | 3548 | 0.008 | 0.023 | 0.029 | 0.100 |
| 集中召唤和变形 | 1200 | 0.008 | 0.061 | 0.100 | 0.148 |

本次采样中每步都在 50 ms 预算内。部署容量还需在目标服务器上用多局并发、快照编码和真实连接测量。

## 接入表现与扩展内容

[近战兵与艾希的动作接入、素材来源与浏览器性能实测](模型与动作首批验证.md) · [三阶段表现层规划](表现层接入规划.md)

- **表现协议**　战场 WebSocket 的 `frame.protocol = 2`。单位由 `id` 标识，同一单位变蛋或孵化会保留 ID。位置、朝向、当前动作、施法时间、弹道和区域来自席位快照。攻击、发射、命中、变形与指令执行结果来自 `presentation.events`。首次连接和事件窗口过期时，以完整快照建立基线。正常连接只消费大于上次游标的事件。每个席位有独立游标。
- **玩家指令**　客户端发送最近可见的 `inputTick`、连续序号和手牌版本。宿主接受后扣费，打牌同时轮换手牌，并在收据中返回 `executeTick = inputTick + 10`。连续收到重复序号、超出时间窗或过期手牌会拒绝。主动技绑定提交时的单位，执行时重新检查状态。控制导致取消会退回费用，施法单位死亡则作废。等待执行的命令和最终结果都按席位下发。
- **卡牌与技能**　卡牌元数据放在 `content/catalog.json`，实战参数放在 `content/battle_rules.json`。卡组、规则、技能图和备战说明通过稳定技能 ID 关联。复用已有机制的普通卡可以直接登记。新机制在内核实现后，把机制加入构建校验并补对应的行为测试。运行 `cargo test --workspace --locked` 会检查已登记的卡牌、技能、图片和代表性行为。
- **地图与模式**　`content/maps.json` 定义世界尺寸、障碍、双方塔位、出兵点、部署区、倒塔后解锁的区域和地面投影。`content/modes.json` 绑定地图并定义比赛时长、经济阶段和兵线时刻。经典模式使用两个席位、八张卡和两个主动槽。改变队伍数或胜利条件需要扩展模式逻辑。启动时设置 `LOBBY_TEST_MAP=1` 后，房主可选择“交错桥测试场”。对同一个大厅运行 `TEST_CROSSING=1 npm --prefix web run test:lobby` 可验证新地图上的双人对局。
- **恢复与发版**　每场比赛冻结规则指纹、内容版本、种子、地图和双方卡组。宿主持久化人类与 AI 的输入、接收帧和顺序，用同一构建重启可恢复待执行命令。上线规则变更前，在旧宿主启动环境中配置 `LOBBY_DRAIN_FILE`。发版时创建这个标记文件，等 PostgreSQL 中尚无结果的 `pending` 和 `claimed` 对局清空，再切换宿主并移除标记。未入场的房主可撤回备战。保留旧二进制及其配套网页资源以恢复旧局。宿主只恢复指纹匹配的对局，已有终局仍可直接读取。
