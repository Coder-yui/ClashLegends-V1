# 近战兵与艾希 · 模型和动作首批验证

2026-11-19 首批验证时，正式经典战场使用 Three.js 绘制艾希、蓝方近战兵和红方近战兵。两边使用同一个权威战场，玩家各自从己方水晶方向观看。当时其余单位沿用调试图形；艾希的箭采用简单线段标出飞行路径。已接入模型的单位在加载期间也不会绘制几何占位。性能工具的 `?battleView=debug` 会关闭模型层，用于测量基础绘制开销。

## 素材与动作

| 单位 | WAD 和原皮动画图 | 实战选片与关键标记 |
| --- | --- | --- |
| 艾希 | Champions/Ashe.wad.client，角色 ashe | Idle1、Run、Attack1/2、Spell2、Death。两个普攻 SpellObject 的 castFrame 均为 9，发射骨骼均为 R_hand。 |
| 近战兵 | Maps/Shipping/Map11.wad.client，角色 sru_orderminionmelee、sru_chaosminionmelee | 两方分别读取自己的皮肤动画图。两个基础攻击片段各用其角色的第 11.8 帧作为接触点。红方部分片段由图引用蓝方目录里的共享 ANM。 |

模型、骨架、原皮纹理和入选动作从本机原生包重建。离线打包保留具名节点并压缩网格和动画，三个自包含 GLB 合计 1,287,964 字节。每种造型共享几何、材质和动作，场上各实例独立计算姿势。已经构建的前后端可直接运行。重新制作资产时，先安装 web 依赖并配置本机 lol-asset-tools，再在根目录执行 `python3 tools/import_battle_models.py /Users/czh/Downloads/LOL_Asset_Source`。[转换工具](../../tools/import_battle_models.py) · [模型与剪辑映射](../../web/src/battle-motion.ts)

内核每次起攻保存起手 Tick、预计释放 Tick、恢复结束 Tick、攻击轮次及释放状态。前摇中会按实际攻击时钟修正释放时间。攻击和施法各有自己的时间线。宿主提供释放、取消、弹体生成、命中和死亡事件。浏览器缓冲两步，插值地面位置与转向，保持跑步循环相位。攻击标记两侧分别映射到对应时间段，下一击接续时从当前混合姿势进入。断线后按动作年龄恢复，已离手的弹体继续按公开快照绘制。[核心出手时钟](../../battle-core/src/combat.rs) · [席位事件](../../server/src/presentation.rs) · [显示时钟](../../web/src/battle-clock.ts) · [骨骼与挂点采样](../../web/src/battle-models.ts)

## 实战验证

两个独立 Chrome 会话通过正式好友房配置卡组、准备并进入晴昼峡谷。双方在同一座桥部署，截图和录屏沿用正常玩家相机。记录中保留了服务器发送的席位帧。

- **录像对应对局**。两端各采样到 11 次艾希手部发射和 49 次近战兵接触。两类单位都走过两套普攻片段。艾希的一轮从 Tick 48 起手，Tick 50 离弦；近战兵的一轮从 Tick 111 起手，Tick 117 接触。动作采样落在配置的源标记上，显示时间线首次处理标记的最大滞后为 1 个 Tick。该数值包含渲染帧采样间隔，网络输入延迟另计。
- **中断与恢复**。这一局有 3 次前摇取消，其中 2 次来自近战兵。浏览器刷新后直接恢复当前实体和姿势，首帧历史发射计数为零。Rust 回归另外覆盖冻结撤销未释放攻击、解冻后新一轮攻击、射手死亡后已释放弹体继续命中。
- **最终配置复验**。加入己方手牌模型预加载后，用另一场双人对局复验。两端各记录 22 次艾希离弦、43 次近战兵接触，浏览器回归通过。

实战入口为 `node web/tests/battle-actions.mjs`，默认使用运行中的本机 4317 开发大厅；可设置 `LOBBY_URL` 指定隔离的开发服务。脚本创建新的好友房并将席位记录的本机临时路径打印到终端。[双席位实战用例](../../web/tests/battle-actions.mjs)

## 帧时间

Apple M5，macOS 26.6.2，Chrome 157，ANGLE Metal，800 × 900 CSS 像素。对同一份席位记录逐次打开几何视图和模型视图，预热约 2 秒，截取约 4.5 秒稳态样本。密集场景固定 1/8 艾希、7/8 近战兵，混合移动和交替攻击。32／64／128 是人为设置的同屏骨骼实例数。复验命令为 `node web/tests/battle-render-load.mjs <上一步输出的记录文件>`。[渲染对照用例](../../web/tests/battle-render-load.mjs)

下表单位均为毫秒。主线程用时包括插值、骨骼求值、绘制提交与调试图层绘制。帧间隔包含浏览器调度和显示节奏。数据用于判断这两类模型在当前桌面设备上的开销，移动端真机、冷启动峰值和后续复杂角色仍需分别测量。

| 场景 | 几何视图主线程 p95 | 模型视图主线程 p95 | 模型帧间隔 p50 | 模型帧间隔 p95 | 模型帧间隔 p99 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 实战片段，最多 7 个模型 | 0.3 | 1.2 | 16.7 | 18.2 | 18.9 |
| 32 个骨骼单位 | 0.3 | 3.1 | 16.7 | 18.3 | 19.1 |
| 64 个骨骼单位 | 0.4 | 4.0 | 16.7 | 18.5 | 19.9 |
| 128 个骨骼单位 | 0.7 | 3.4 | 16.6 | 18.3 | 18.9 |

每组约 280 帧。128 单位对应 128 次模型绘制。此次短窗口里 64 单位的主线程 p95 高于 128 单位，宜用多轮、长时间运行评估容量趋势。模型视图在实战片段的最长帧间隔为 25.3 ms。约 60 FPS 的中位帧率与偶发较慢帧可以同时出现。

## 英雄、变身与衍生物

工作台「模型与动作」可以直接选择英雄及衍生单位。有第二种形态的对象提供形态选择，有独立死亡后续模型的对象提供模型阶段选择。混编卡可以分别检查其成员。「实战观察」使用正式战斗内核的攻击、施法、变身、控制和死亡时间线。

新版使用旧卡配置选定的 LoL 模型、包装缩放及原生动作。离线导出也会执行旧模型的动画准备步骤，以保留纳尔的组合变身和格雷福斯的移动装填等片段。网页运行时通过 Three.js 骨骼和新版动作系统播放。每个造型的本体、移动、普攻和其他基础动作共用一个 GLB，可选技能独有的片段另行打包。纯法术通过实际召唤对象进入模型清单。

从新版仓库根目录可以重新生成这一批资源。导出目录用于存放压缩前的临时 GLB。

```sh
export_dir=$(mktemp -d)
/Applications/Godot.app/Contents/MacOS/Godot --headless --path ../ClashLegends --script "$PWD/tools/export_roster_visuals.gd" -- "$export_dir"
python3 tools/import_roster_models.py "$export_dir"
node tools/model-resources.mjs
python3 tools/import_review_animations.py ~/Downloads/LOL_Asset_Source ../ClashLegends/assets "$export_dir"
npm --prefix web run build
cargo test --workspace --locked
```

工作台的预览导入先保留完整场景里的片段，再从对应造型的 LoL 动画图和 ANM 文件补齐缺失动作。同一 ANM 的具名动作槽复用骨骼轨道。生成的独立压缩包位于 `web/public/review-animations/`，索引为 `web/src/model-review.json`。调整模型、形态或动作绑定后重新生成。

对正在运行的本地审查服执行以下两项浏览器验证。第一项为每种造型采集实渲像素并播放绑定片段。第二项逐卡部署、检查代表技能与变身，并记录双方正式对局的实际资源请求。

```sh
LOBBY_URL=http://127.0.0.1:4432 node web/tests/roster-models.mjs
LOBBY_URL=http://127.0.0.1:4432 node web/tests/roster-actions.mjs
```

本次在 macOS 26.6.2、Chrome 157、800 × 900 CSS 像素下，用正式对局页面重放相同帧，交替驱动八种英雄造型的移动和普攻。以下为预热后的密集场景测量。帧间隔包含浏览器调度与显示刷新，CPU 列为战场绘制调用的耗时。

| 同屏骨骼实例 | 渲染 CPU P95 | 帧间隔 P50 | 帧间隔 P95 | 最大绘制调用数 |
